# Project workflow

- The user authorizes creating and maintaining the public GitHub repository `espitman/GravityRoom-VR`.
- Commit and push completed, verified project changes at meaningful milestones without asking for permission again. Review the diff and run checks appropriate to the change first.
- Keep commits focused. Preserve unrelated user changes. Do not force-push or rewrite published history without explicit authorization.
- Never commit credentials, signing keys, private files, or generated Unity caches/builds. Check third-party asset redistribution permissions before publishing assets.
- Follow `PROJECT_PLAN.md`. Mark items complete only when their work is complete, and in the same edit add the contributing model(s) and per-model token accounting directly beneath the item.
- Use actual reported model identities and task-specific token counts, with input/output/total and source when available. If unavailable, write `نامشخص` with a brief reason; do not invent counts or assign whole-session usage to individual tasks. Identify a CLI separately from its underlying model.
- Prefer Sol and `agy` CLI for routine work when available and suitable. Reserve Astra for heavy, important, exceptional tasks.
